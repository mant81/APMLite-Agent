# 검증 계약

## 서비스 무영향 조건

DB 연결 실패, 대시보드 중단, 저장 큐 포화, 계측 예외 상황에서도 대상 요청이 정상 처리되어야 한다. 측정 데이터가 누락되는 것은 허용하지만 대상 요청 실패나 지속적인 지연 증가는 허용하지 않는다.

## 기준 제품 비교

WAS 모니터링을 기본 기능 범위로 삼고 기준 APM 제품을 벤치마크로 사용한다. 제품명은 기록하지 않는다. 비교는 관찰 가능한 기능과 수치로 제한하고, 제품 내부 구현이나 미측정 성능을 추정하지 않는다. 모든 비교 결과에는 `parity`, `partial`, `gap`, `unknown` 중 하나를 붙인다.

최소 비교표는 접속자 수, TPS, 동시 접속자 수, 히트 수, JVM/GC 지표, WAS 트랜잭션·응답시간, SQL 추적, 느린 쿼리, 스레드·오류, 대시보드, 샘플링 오버헤드, 히트 수 기반 경고 분석, 보존·접근 제어로 구성한다.

히트 수 기반 경고는 시간 창, 임계값, 집계 대상(전체 서비스·URI·트랜잭션), 중복 알림 억제, 경고 해제 조건을 함께 검증한다. 단순히 포트가 열렸는지 확인하는 것으로는 통과시키지 않는다.

필수 검증은 `mvn -B test`와 패키징 빌드다. 테스트 소스가 없으면 이를 명시한다.

DB 없이 `use_db=false`로 에이전트를 실행하고 다음을 확인한다.

- health의 status가 UP이다.
- overview의 timestamp가 두 샘플 사이에서 증가한다.
- timeline에 두 개 이상의 샘플이 있다.
- 대시보드와 SQL API가 유효한 응답을 반환한다.

MariaDB 저장은 별도 서비스와 자격 증명이 필요하므로 기본 smoke의 필수 조건이 아니다.
